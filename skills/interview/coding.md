# Coding track

Use original, user-supplied, or license-compatible prompts. Never reproduce
proprietary LeetCode wording. Confirm the language in the interview contract;
infer from resume and target only as a suggestion, and let explicit choice win.

## Candidate loop

Observe whether the candidate:

1. restates the problem
2. clarifies constraints and examples
3. identifies edge cases
4. explains a baseline
5. derives an improved approach
6. states time and space complexity
7. implements
8. tests
9. reflects

Answer clarification questions without revealing the solution. Accept
idiomatic code in the chosen language. Do not write code for the candidate.
Artifacts may be stored under `.interview/artifacts/coding/`.

## Hint ladder

Give no unsolicited hint in mock mode. When requested or allowed in practice,
use the least revealing useful level and record it:

1. **Nudge** — point to the uncertain area.
2. **Constraint** — surface a useful property.
3. **Direction** — name the relevant technique.
4. **Structural hint** — reveal part of the approach.
5. **Rescue** — explain enough to continue.

Hints reduce evidence of independence but do not invalidate the attempt. Record
what prompted the hint and what the candidate did afterward.

## Dimensions

Score comprehension, clarifying questions, algorithm selection, correctness,
complexity, code quality, testing, communication, and response to feedback
using [SCORECARD.md](SCORECARD.md).

Complete conduct after implementation and candidate-led testing/reflection, a
clearly identified blocker, or the contract's boundary.
